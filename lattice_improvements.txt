Requests for the Lattice developers, from the defense deck.

1. A stepping Graphviz diagram (slide "Union of Incoming Contexts", src/background.md)

   Need: the interval lattice of thesis figure 2 beside the abstract interpretation, with nodes and
   edges highlighted step by step (operands of a union, its result, the widening edge).
   Today: `dot` is static, and `graph-anim` only draws circles laid out by Lattice (no boxes, no
   dashed or dotted edges, no "..." stubs, no ranks chosen by the author). The deck therefore ships a
   local plugin, `hasse-anim` (src/lattice_plugins.py, src/plugins/), that lays out a .dot file once
   and sets a state per node and edge per position.
   Wanted syntax, roughly what the plugin does:

     ```dot-anim {#lat file="figures/interval-lattice.dot" height=470}
     steps:
       - null
       - nodes: {s0: active, s1: active}
         caption: "{0} ∪ {1}"
       - nodes: {i01: done}
         edges: {s0->i01: path}
     ```

   with the theme states of graph-anim, deltas between steps, DOT `class="hidden"` for elements
   drawn only when a step names them, and its nodes and edges as arrow parts (`lat.mf1`,
   `lat.i02->mf1`), as the plugin already provides.

2. The panel of abstract-interp-anim at `panel_at: right` is capped at 40% of the width, so a
   widening chain such as `∇ [0, maxfix-1]` wraps inside its chip. An option for the panel width (or
   letting the history list take the room it needs) would allow the panel beside a narrow CFG.

3. A stylesheet for the deck (slide "Object of this Thesis", src/preface.md)

   Need: one sentence set large in the middle of the slide, with its key phrases in the accent
   colour (the statement of the thesis object).
   Today: CSS reaches a deck only through a component's `css` list, and the helper classes
   (`.center`, `.small`) do not change the size or colour of text. A custom container
   (`::: statement`) gives the class but no way to ship its CSS. The deck therefore ships a static
   local plugin, `statement` (src/lattice_plugins.py, src/plugins/statement.css), whose only purpose
   is to carry that CSS.
   Wanted syntax: a front matter key listing stylesheets, paths relative to the root file,

     ---
     css: [styles/deck.css]
     ---

   embedded after the theme so that its rules may use and override the `--lt-*` variables. Then
   `::: statement` with `**key phrases**` in Markdown would replace the plugin.

4. A fragment revealed out of document order (slide "Native Multi-Return Functions", src/future-work.md)

   Need: the code in the right column appears with the second bullet of the left column, and a
   callout below the bullets, in the left column, appears after it.
   Today: fragments are numbered in document order, so `{.reveal-with}` on the code would join the
   callout, written before it. The slide instead opens the code column with a `width` cue in place
   of an empty column of the same width (`native-code-col=1fr native-room=0`), so that the bullets
   do not move. The callout is pushed to the bottom of its column by wrapping the bullets in a
   nested `columns` (which grows with flex: 1), since there is no way to align a block to the bottom.
   Wanted syntax: an explicit fragment number, and a helper class for bottom alignment, roughly

     {.reveal at=2}
     ```code {file="programs/hvm-hyperfunction.hvm"}
     ```

     {.reveal .bottom}
     ::: callout

5. A figure with a credit line, drawn in the theme's ink (slide "Remerciements", src/conclusion.md)

   Need: a black and white drawing (a scanned book illustration) beside the acknowledgements, with
   a small attribution under it, the drawing taking the theme's ink colour.
   Today: `![alt](file.png)` has no caption and keeps the image's own colours, and the text styling
   needs CSS (request 3). The deck therefore ships a local plugin, `thanks` (src/lattice_plugins.py,
   src/plugins/thanks.css), that embeds the PNG as a CSS mask filled with `--lt-ink`.
   Wanted syntax, roughly:

     ![Un voilier sous la pluie](figures/dream-of-islands.png){height=460 ink=true caption="*A Dream of Islands*, Philip Teece, p. 33"}

6. A fragment shown for a few steps only, taking no room (slides "Static Analysis Overview",
   src/background.md, and "Core idea of Lambda Versioning", src/lv.md)

   Need: a related-work note that appears for one step (while the speaker comments on it) and then
   goes away, so that the blocks revealed next can use its space.
   Today: a fragment, once revealed, stays until the end of the slide, and its room is kept from the
   first step (`visibility: hidden`), so a note on a full slide does not fit. The deck therefore
   gives its local plugin `related-work-note` (src/lattice_plugins.py, src/plugins/) a `flash: true`
   mode: the block becomes a three-position track (hidden, shown, hidden) moved in the timeline
   (`rw 1`, then `rw end`), and while shown it is laid over the blocks that follow it, from a
   zero-height slot (whose flex gap is given back with a `:has()` rule in the plugin's CSS).
   Wanted syntax, roughly: a fragment with an end, and an overlay placement,

     {.reveal until=+1 overlay=true}
     ::: callout

7. Table columns shown step by step, with the best value per row computed (slide "Bigloo and
   Gambit Are Already Fast", src/experiments-sbbv.md)

   Need: a results table that opens without some of its columns (the SBBV ones), then adds them
   in one step, the highlight (fastest time of each row) moving to the new winners.
   Today: a GFM table is static, `{.reveal}` works on whole blocks, and bold is written by hand,
   and there is no way to highlight a cell, so the mark cannot differ between steps. The deck therefore ships a local plugin, `table-steps`
   (src/lattice_plugins.py, src/plugins/table-steps.js and .css), that takes the table in its YAML
   body, hides and shows columns per position, highlights the best value among the columns shown (light yellow), and
   glides the columns that stay to their new places.
   Wanted syntax, roughly what the plugin does:

     ```table-steps {#times}
     best: min
     table: |
       | Program | Node.js | Bigloo | Bigloo + SBBV | ...
       |---------|--------:|-------:|--------------:| ...
     steps:
       - hide: [Bigloo + SBBV, Gambit + SBBV]
       - show: [Bigloo + SBBV, Gambit + SBBV]
     ```

   or, closer to plain Markdown, column attributes on a GFM table (a reveal step per column) and a
   `best=min` attribute on the table.

8. A detour badge that appears at the last step without making the detour a step (slide "Conclusion",
   src/conclusion.md)

   Need: the "Thank you!" badge, bottom right of the Conclusion slide, appears after the last takeaway
   and enters the acknowledgements detour only by its key (m), Down or a click, never by Right.
   Today: `badge=step` and `badge=next` need the detour to be a detour step (LT055), and a detour step
   is entered by Right. A reveal on the badge itself is refused (LT056, LT065). The deck therefore
   wraps the badge in a container that is a reveal fragment, and adds a `reveal 1` line at the end of
   the timeline:

     {.reveal}
     ::: thanks-corner
     ::detour-badge{ref=detour-thanks}
     ::: /thanks-corner

   plus a rule in src/plugins/thanks.css to put the wrapper at the bottom right (there is no helper
   class for that either, see request 4). The wrapper and the extra timeline line are noise.
   Wanted syntax, roughly: a badge mode tied to a step but not to a detour step,

     ::detour-badge{ref=detour-thanks badge=at at=end}

   or `badge=end` for the last step of the slide, and, still in the same spirit as request 4, a
   helper class for alignment (`.bottom-right`) usable on a placed badge.
